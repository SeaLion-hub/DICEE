# Cache Stampede (Thundering Herd) 방어 전략

## 배경 (Context)
사용자 트래픽이 몰리는 수강신청이나 주요 공지 발표 시, 메인 화면 공지사항 목록 데이터를 담은 Redis 캐시(Hard TTL)가 만료되는 짧은 찰나에 수천 명의 조회가 겹치면 모든 요청이 동시에 DB로 쏟아집니다. 이로 인해 제한된 DB 커넥션 풀이 즉시 고갈되고 전체 시스템이 다운되는 '캐시 스탬피드' 취약점이 있었습니다.

## 결정 (Decision)
단순한 `EXPIRE` 명령어를 넘어선 상용 서비스 수준의 **Soft TTL + Mutex Lock** 방어 패턴을 `app/core/redis.py`에 도입했습니다.
1. **Soft TTL (논리적 만료):** 실제 데이터와 함께 더 짧은 생명주기를 가진 `soft_ttl` 타임스탬프를 JSON으로 묶어 저장합니다.
2. **Mutex Lock (분산 락):** `soft_ttl`이 만료되었을 때, 수많은 동시 코루틴 중 `SETNX` 명령을 통해 락을 획득한 단 **1개의 요청만** DB를 조회하여 캐시를 갱신하게 합니다.
3. **Stale Data 반환:** 락 획득에 실패한 나머지 수천 개의 요청은 대기하지 않고, 방금 읽어온 '약간 오래된(Stale)' 캐시 데이터를 즉시 반환하여 응답 지연을 방지합니다.

## 결과 (Consequences)
- 캐시가 갱신되는 순간 초당 수만 건의 트래픽이 폭증하더라도 원본 DB로 향하는 쿼리를 정확히 **1개**로 통제하여 DB 붕괴를 완벽하게 차단합니다.
- 사용자 경험(UX) 측면에서 무한 로딩이나 500 에러를 겪지 않게 됩니다.
